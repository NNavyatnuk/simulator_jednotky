# Shifting Unit: безпечний CAN/TWAI self-test (PlatformIO)

Це **окремий діагностичний проєкт**, не оригінальна прошивка TUL Racing.
Він не викликає `pistonUp`, `pistonDown` чи `shiftGears` і не ставить GPIO7/8 у HIGH.

## Що перевіряється

- ESP32 завантажує діагностичну програму;
- TWAI-драйвер встановлюється і запускається на 1 Мбіт/с;
- ESP32 у режимі `TWAI_MODE_NO_ACK` відправляє 4 **тестові** CAN-кадри;
- завдяки self-reception кожний кадр приймається назад та порівнюються ID і 8 байтів.

У тестах використовуються **вигадані ID 0x321–0x324**, а НЕ ID керма чи ECU боліда.
Дані імітують байт команди UP/DOWN/N та байт передачі — **це лише перевірка передачі даних, не виконання перемикання**.

## Підготовка — обов'язково

1. Плата повинна бути **лише на USB**, без CAN-проводів, живлення автомобіля, соленоїдів, пневматики або інших навантажень.
2. Відкрий окрему папку `shifting-unit-can-selftest` як проєкт у VS Code + PlatformIO. **Не копіюй `main.cpp` у бойову прошивку.**
3. Перевір у Windows → `Správce zařízení` фактичний COM-порт CP2102. У `platformio.ini` зараз `COM5`; якщо номер змінився, онови `upload_port` і `monitor_port`.
4. Натисни `PlatformIO: Upload`, а коли завершиться — `PlatformIO: Monitor` (115200 baud).
5. У консолі мають бути `TWAI driver installed`, `TWAI started`, рядки `TX` і `RX`, підсумок `Result: 4 / 4 frames passed`. Якщо пропустив повідомлення, введи `t` у Serial Monitor або натисни RESET на платі за наявності.

## Що означає результат

- `4 / 4`: успішна одиночна перевірка TWAI self-reception на платі. Це не підтверджує правильність **справжньої** CAN-шини керма, штатної `shifting.cpp`, MOSFET або пневматики.
- `0 / 4` чи timeout: слід перевірити TWAI-схему, трансивер, живлення, узгодження CAN та настройки. Один невдалий self-test ще не є доказом несправності плати.
- Драйвер не запустився: виправляємо ініціалізацію.

## Після тесту

Повертайся до основного проєкту `shifting-unit-firmware-main` і завантажуй штатну прошивку **лише після перевірки її логіки та відключення виконавчих механізмів**.

Для перевірки реального фізичного CAN-зв'язку з **іншим** пристроєм потрібен USB-CAN адаптер (з CAN-контролером і трансивером) або другий повноцінний CAN-вузол, а також правильні CAN_H, CAN_L, заземлення, термінування і швидкість.
